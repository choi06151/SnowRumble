# 기존 Task 마이그레이션 장부

## 목적

구조 개편 전 Task와 구현을 삭제하지 않고 새 GDD와 4인 역할별 Task에 연결합니다. 기존 `완료`는 당시 범위의 검증 이력이며 새 기획의 완료를 뜻하지 않습니다.

## 분류 기준

- `유지`: 새 기획에서도 동작과 책임을 그대로 사용
- `수정`: 기존 구현을 기반으로 규칙이나 범위를 변경
- `대체`: 핵심 규칙이 달라 새 Task 결과로 교체
- `폐기`: 더 이상 사용하지 않되 참조 확인 전 파일은 삭제하지 않음
- `재검증`: 구현은 유지하되 새 통합 환경에서 다시 확인

## 기존 진행중 선점 처리

- 구조 개편 전 `PLANS.md`에 있던 선점은 기존 구현 이력으로 보존합니다.
- 새 역할별 Task를 실제로 시작할 때 메인 프로그래머가 기존 작업 브랜치와 변경을 확인하고 새 선점을 기록합니다.
- `SnowRumbleCharacter.h/.cpp`처럼 여러 기존 Task가 동시에 가리킨 파일은 C 담당 공용 파일로 보고 계약 없이 다른 역할이 수정하지 않습니다.
- 기존 `.uasset`과 `.umap`은 새 자산 수정자가 확정되기 전 누구도 이름 변경·이동·덮어쓰지 않습니다.
