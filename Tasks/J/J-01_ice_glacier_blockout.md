# Task J-01 - 얼음 빙하 블록아웃

## 설명

1vs1~4vs4 전투와 단계별 수위 상승을 고려한 얼음 빙하 맵의 기본 지형·동선·고저차를 구성한다.

## 범위 해석

- J-01은 Level Editor와 `.umap` Blockout으로 플레이 가능한 공간 구조를 잡는 Task다.
- 0~4분, 4~5분, 5~6분, 6분 이후 구간은 J-02 수위 상승 로직을 얹기 위한 높이·공간 분류 기준으로만 사용한다.
- 팀 시작, 기본 눈덩이, 선물상자 Spawn Point, 모닥불 후보는 실제 Gameplay Actor 연결 전 임시 표식 또는 후보 공간으로 먼저 잡는다.
- 수위 상승 Actor, 얼음물 Damage, 경고 UI, 서버 판정, Blueprint Gameplay 로직은 J-02 이후 범위다.

## 상태 전이 기준

- 시작 가능: 즉시
- 완료 가능: 블록아웃 동선과 침수 단계별 영역 검토 완료

## 구현 항목

- [ ] 1vs1~4vs4에서 너무 넓거나 좁지 않은 전체 플레이 영역을 잡는다.
- [ ] 양 팀 시작 후보에서 중앙 전투 공간까지 공정하게 접근할 수 있는 주동선을 만든다.
- [ ] 중앙·외곽·저지대·고지대를 구분해 수위 상승 단계가 공간으로 읽히게 한다.
- [ ] 얼음길, 빙벽, 다리, 절벽, 고지대 같은 빙하 테마 구조를 Blockout 형태로 배치한다.
- [ ] 좁은 길과 넓은 전투 공간의 비율을 조정해 전투·회피·우회가 모두 가능하게 한다.
- [ ] 팀 시작·기본 눈덩이·선물상자 TargetPoint·모닥불 후보 공간을 마련한다.
- [ ] 낙사 또는 이동 제한 구역은 공간 경계만 표시하고 실제 처리 로직은 확정하지 않는다.

## 제작 순서

### Phase 1. 플레이 영역과 맵 스케일

- 만드는 것: `L_IceGlacier_J` 후보 맵의 외곽 경계, 중앙 기준점, 플레이 가능 범위.
- 이유: 1vs1부터 4vs4까지 이동 시간이 지나치게 길거나 짧지 않은 기준을 먼저 잡기 위함.
- Editor 확인: Third Person 캐릭터 기준으로 시작 후보에서 중앙까지 이동하며 시야, 이동 시간, 막힘을 확인한다.
- 완료 기준: 중앙 전투 공간과 외곽 저지대가 한눈에 구분되고, 팀별 시작 후보가 대칭 또는 동등한 거리를 가진다.

### Phase 2. 큰 지형 Massing

- 만드는 것: 중앙 빙하 덩어리, 외곽 낮은 얼음판, 절벽 또는 물 경계, 큰 빙벽.
- 이유: J-02의 수위 상승이 낮은 영역부터 잠기는 구조로 읽히게 하기 위함.
- Editor 확인: 0~4분 안정 구간에 남길 넓은 전투 공간과 4분 이후 먼저 위험해질 낮은 영역을 구분한다.
- 완료 기준: 낮은 외곽, 중간 높이 이동로, 중앙 안전 후보가 높이 차이로 식별된다.

### Phase 3. 중앙 / 외곽 구조

- 만드는 것: 중앙 교전장, 외곽 순환로, 중간 엄폐와 복귀 지점.
- 이유: 전투가 중앙으로 모이되 외곽 우회와 후퇴 선택지가 남아야 한다.
- Editor 확인: 중앙이 너무 넓어 전투가 흩어지지 않는지, 외곽이 너무 안전한 우회로가 되지 않는지 확인한다.
- 완료 기준: 중앙 교전장 1곳과 보조 전투 지점 2~3곳이 구분된다.

### Phase 4. 주요 이동 동선

- 만드는 것: 팀별 주동선, 우회동선, 저지대 탈출 동선, 좁은 다리 또는 얼음길.
- 이유: 플레이어가 빠르게 만나되 한 방향 chokepoint에만 갇히지 않게 하기 위함.
- Editor 확인: 양 팀 시작 후보에서 중앙까지 주동선과 우회동선을 각각 걸어본다.
- 완료 기준: 각 시작 후보에서 중앙까지 최소 2개 이상의 선택지가 있고, 막다른 길은 의도한 위험 공간에만 남는다.

### Phase 5. 고저차 / 빙하 구조

- 만드는 것: 고지대 엄폐, 낮은 침수 후보, 빙벽 시야 차단, 다리와 절벽 경계.
- 이유: 수위 상승 전후로 유리한 위치가 달라지는 얼음 빙하만의 공간 리듬을 만들기 위함.
- Editor 확인: 고지대에서 과도하게 넓은 시야가 열리지 않는지, 낮은 곳에서 중앙 복귀가 가능한지 확인한다.
- 완료 기준: 고지대는 이점을 주지만 우회 접근이 가능하고, 저지대는 보상과 위험이 함께 있는 공간으로 보인다.

### Phase 6. Spawn / 전투 공간 확인

- 만드는 것: 팀 시작 후보, 기본 눈덩이 후보, 선물상자 `TargetPoint` 후보, 모닥불 후보를 놓을 빈 공간.
- 이유: J-02에서 Gameplay Actor를 얹을 때 동선과 충돌하지 않게 하기 위함.
- Editor 확인: 시작 후보 주변에 4명까지 흩어질 공간이 있는지, 중앙 근처 상자 후보가 너무 한 팀에 치우치지 않는지 확인한다.
- 완료 기준: 실제 Actor 연결 전에도 각 후보 위치의 역할을 Outliner 이름이나 임시 표식으로 구분할 수 있다.

### Phase 7. Multiplayer Blockout Test

- 만드는 것: 완성 자산이 아니라 이동·시야·충돌 확인용 Blockout 테스트.
- 이유: Listen Server/Client에서 플레이어가 서로 만나고 이동하기 좋은 구조인지 먼저 확인하기 위함.
- Editor 확인: 호스트와 클라이언트가 시작 후보에서 중앙으로 이동해 마주치는 흐름, 우회 접근, 낙하 위험, 카메라 막힘을 본다.
- 완료 기준: 주요 충돌·시야 막힘·일방적인 시작 위치를 기록하고 J-02로 넘길 배치 후보가 정리된다.
