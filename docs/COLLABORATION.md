# Collaboration

## 목적

이 문서는 메인 프로그래머와 SUB 프로그래머가 같은 프로젝트를 함께 작업할 때 역할, 파일 소유권, 교차 검토와 충돌 방지 절차를 정의합니다.

## 역할

### 메인 프로그래머

- 게임 기획, MVP 범위, Task 순서와 완료 조건을 최종 결정합니다.
- 하네스 문서와 프로젝트 규칙을 직접 수정할 수 있는 유일한 담당자입니다.
- 서버 권한, RPC, 복제, 게임 규칙과 Blueprint 연결 지점을 C++로 구현합니다.
- UI를 제외한 Blueprint, 맵, 입력, 모델, 애니메이션, 이펙트, 사운드와 에디터 설정을 담당합니다.
- SUB 프로그래머에게 별도 UI Task와 UI 자산 범위를 배정하고 최종 통합을 담당합니다.
- 두 작업 결과가 충돌하면 어느 변경을 유지할지 결정합니다.
- Unreal 싱글플레이 개발에는 숙련되어 있지만, 멀티플레이 구현은 처음이라는 전제로 네트워크 절차를 확인합니다.

### SUB 프로그래머

- 배정된 Task와 프로젝트 규칙을 읽고 구현 범위가 맞는지 작업 전에 교차 검토합니다.
- 메인 프로그래머가 제공한 이벤트, 함수와 프로퍼티를 사용해 별도 SUB Task의 UI만 구현합니다.
- `WBP_` 위젯, UI 레이아웃, 아이콘, 텍스트, UI 애니메이션과 UI 표시용 조정값을 담당합니다.
- 캐릭터·게임플레이 Blueprint, C++, Config, 맵, 게임 규칙, 입력 판정과 비UI 에셋은 수정하지 않습니다.
- 기준 문서의 문제나 Task 변경 필요성을 발견하면 직접 수정하지 않고 메인 프로그래머에게 수정안을 전달합니다.
- C++ 연결 지점의 부족이나 오류를 발견하면 Blueprint에 중복 게임 규칙을 만들지 않고 메인 프로그래머에게 요청합니다.
- Unreal 개발 숙련도가 낮고 멀티플레이 구현은 처음이라는 전제로, 한 SUB Task에서 위젯 목적과 데이터 흐름 하나씩 구현합니다.

## 기본 소유 범위

### 메인 프로그래머 전용

- `AGENTS.md`
- `docs/`
- `Tasks/`
- `Source/`
- `Config/`
- 프로젝트 파일과 빌드 설정
- `Content/` 아래 UI를 제외한 Blueprint, 맵과 에셋

위 경로는 메인 프로그래머만 직접 수정합니다. SUB 프로그래머는 읽기, 검토, 문제 보고와 수정안 제안만 할 수 있습니다.

### SUB 프로그래머 전용

- 메인 프로그래머가 현재 SUB Task에 배정한 `Content/` 아래 `WBP_` 위젯과 UI 전용 에셋
- 배정된 위젯의 레이아웃, 아이콘, 텍스트, UI 애니메이션과 UI 표시용 조정값

배정된 UI 자산은 SUB Task가 진행되는 동안 SUB 프로그래머가 단독으로 수정합니다. 메인 프로그래머는 충돌을 막기 위해 해당 자산을 동시에 수정하지 않습니다.

### 공유 확인 범위

- 두 프로그래머 모두 전체 문서와 현재 Task를 읽고 문제를 지적할 수 있습니다.
- 두 프로그래머 모두 구현 결과를 실행하고 검토할 수 있습니다.
- 읽기와 검토는 소유권을 바꾸지 않으며, 수정은 담당자의 전용 범위를 따릅니다.

## 예외 배정

- 기본 소유 범위를 바꿔야 하면 메인 프로그래머가 구현 시작 전에 현재 Task의 `작업 배정`에 대상 경로와 이유를 기록합니다.
- 예외는 경로 또는 파일 단위로 한정하며 `Source/`, `Content/`, `docs/` 전체처럼 넓게 부여하지 않습니다.
- 한 파일이나 Unreal 자산에는 동시에 한 명의 수정 담당자만 둡니다.
- 배정되지 않은 파일이나 자산은 수정하지 않습니다.

## 작업 배정

메인 프로그래머는 구현 시작 전에 현재 Task에 다음 항목을 기록합니다.

- 메인 Task 담당자
- SUB UI Task 담당자
- 메인 프로그래머 선점 파일
- SUB 프로그래머 선점 UI 자산
- 공유 확인 대상
- 인계 조건
- 병합 또는 반영 순서

실제 파일이나 자산 이름을 아직 알 수 없으면 구현 승인 전 조사한 결과로 배정을 확정합니다. 확정 전에는 두 프로그래머 모두 해당 대상을 수정하지 않습니다.

## 충돌 방지 절차

1. 두 프로그래머가 현재 Task, 선행 Task와 관련 규칙을 읽습니다.
2. 메인 프로그래머가 변경 후보 파일과 SUB 프로그래머에게 배정할 자산을 확정합니다.
3. 두 프로그래머가 서로의 범위와 연결 지점을 검토합니다.
4. 메인 프로그래머가 게임플레이와 UI용 C++ 연결 지점을 구현하고 실제 이름과 사용 방법을 SUB Task의 `사전 전제`와 `수동 작업`에 기록합니다.
5. SUB 프로그래머가 인계된 연결 지점만 사용해 배정된 위젯과 UI 에셋을 완성합니다.
6. 두 프로그래머가 호스트와 클라이언트 결과를 함께 확인합니다.
7. SUB 프로그래머가 발견한 문서·Task·C++ 수정 필요 사항을 메인 프로그래머에게 전달합니다.
8. 메인 프로그래머가 기준 문서와 Task를 갱신하고 최종 통합합니다.

## 동시 작업 규칙

- 같은 로컬 작업 폴더를 두 사람이 동시에 수정하지 않습니다.
- 각 프로그래머는 별도 Git 브랜치와 별도 worktree 또는 별도 clone을 사용합니다.
- Unreal `.uasset`과 `.umap`은 병합 가능한 텍스트로 간주하지 않습니다. 하나의 자산은 한 브랜치에서만 수정합니다.
- 상대 작업을 받기 전에는 자신의 미완료 변경을 커밋하거나 안전하게 분리합니다.
- 병합 순서는 메인 Task의 C++·게임플레이 Blueprint 반영 후 SUB Task의 UI 자산 반영을 기본으로 합니다.
- 다른 담당자의 변경이 있는 파일이나 자산은 덮어쓰기, 되돌리기, 이름 변경 또는 이동하지 않습니다.

## 충돌 발견 시

- 충돌 가능성을 발견하면 해당 대상의 수정을 즉시 중단합니다.
- 양쪽 변경을 임의로 합치거나 한쪽을 삭제하지 않습니다.
- 현재 담당자, 각 변경 목적, 겹치는 파일 또는 자산과 필요한 결정 사항을 메인 프로그래머에게 보고합니다.
- 메인 프로그래머가 담당 재배정이나 병합 순서를 결정한 뒤 작업을 재개합니다.

## AI 에이전트 적용

- AI는 작업 시작 전에 자신이 메인 프로그래머 역할인지 SUB 프로그래머 역할인지 확인합니다.
- 역할이 명시되지 않았으면 기준 문서와 Task를 수정하지 않고 사용자에게 역할을 확인합니다.
- 메인 프로그래머 역할의 AI만 메인 프로그래머 전용 범위를 수정할 수 있습니다.
- SUB 프로그래머 역할의 AI는 배정된 UI 자산 작업과 읽기·검토만 수행합니다.
- AI는 다른 작업자가 만든 변경을 자신의 변경으로 간주하거나 정리하지 않습니다.
