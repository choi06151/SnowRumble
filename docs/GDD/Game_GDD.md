# SnowRumble 게임 기획서

## 1. 프로젝트 개요

- 제목: `SnowRumble` (`눈싸움 대소동`)
- 장르: 3인칭 멀티플레이 파티 PvP 스포츠
- 플랫폼: PC 우선, 콘솔·모바일 추후 대응
- 엔진: Unreal Engine 5.8
- 대표 경기 구성: 4vs4
- 방 인원: 최소 2명, 최대 8명
- 네트워크: Listen Server, OnlineSubsystem NULL, LAN Session
- 기획 의도: 눈으로 만든 무기와 아이템, 맵 환경을 활용해 겨울 최고의 팀을 가리는 캐주얼 눈싸움 경기

### 게임 컨셉

눈 덮인 마을 사람들은 매년 겨울 가장 큰 축제인 `SnowRumble Championship`을 개최한다. 마을을 대표하는 팀들은 눈으로 만든 무기와 전략으로 승부하며, 우승팀은 겨울 최고의 팀이라는 명예를 얻는다.

### 세계관

오래전부터 눈이 내리는 계절이면 마을 사람들은 서로 눈을 던지며 놀았다. 단순한 놀이는 시간이 지나며 팀과 규칙을 갖춘 스포츠가 되었고, 주변 마을까지 참가하면서 SnowRumble은 겨울을 대표하는 축제로 성장했다.

## 2. 전체 플레이 구조

`게임 실행 → 메인 로비 → 방 만들기 또는 참가 → 게임 대기방 → 랜덤 팀 배정 및 준비 → 랜덤 맵 로딩 → 팀 PvP 라운드 → 결과 화면 → 다음 라운드 또는 대기방 복귀`

- 기본 모드는 팀 PvP다.
- 한 매치는 3판 2선승으로 진행한다.
- 각 라운드는 약 6분을 목표로 하지만 6분이 지났다는 이유만으로 종료하지 않는다.
- 라운드가 길어지면 맵별 환경 규칙으로 이동 가능 영역을 줄여 전투를 유도한다.
- 각 라운드의 맵은 서버가 무작위로 결정한다.
- 대기방에서 플레이어 또는 호스트가 맵을 직접 선택하지 않는다.
- 한 매치 안에서 여러 맵을 경험할 수 있도록 직전 라운드의 맵은 가능한 한 다음 추첨에서 제외한다. 정확한 중복 방지 방식은 구현 Task에서 확정한다.

## 3. 매칭과 방 설정

### 방 만들기

플레이어가 Listen Server 방을 직접 생성한다.

| 설정 | 기본값 |
| --- | --- |
| 방 이름 | 플레이어 이름의 방 |
| 최대 인원 | 8명 |
| 최소 시작 인원 | 2명 |
| 게임 모드 | 팀 PvP |
| 맵 | 서버가 라운드마다 무작위 선택 |
| 팀당 최대 인원 | 4명 |
| 비밀번호 | 사용 안 함, 선택 설정 가능 |

### 경기 시작 인원 규칙

- 양 팀의 인원수가 같아야 경기를 시작할 수 있다.
- 최소 구성은 1vs1, 최대 구성은 4vs4다.
- 1vs2, 2vs3처럼 양 팀 인원이 다른 상태에서는 시작할 수 없다.

## 4. 메인 로비와 커스터마이징

### 메인 화면

- 화면 중앙에 플레이어 캐릭터가 서 있고 뒤쪽에는 로비 배경 맵을 표시한다.
- 플레이어가 마지막으로 선택한 외형을 메인 화면 캐릭터에 반영한다.

### 메인 메뉴

- 빠른 게임
- 방 만들기
- 방 참가
- 옵션
- 게임 종료
- 캐릭터 꾸미기

### 캐릭터 커스터마이징

- 기본형 인간 형태의 귀엽고 둥근 실루엣을 사용한다.
- 기본 캐릭터에는 목도리를 사용하지 않는다.
- 캐릭터에 자유롭게 그림을 그릴 수 있는 드로잉 기반 커스터마이징을 제공한다.
- 얼굴 표정 선택 기능은 기존 기획대로 유지하고 드로잉 기능과의 적용 우선순위는 구현 전에 확정한다.
- 부츠, 장갑, 패딩은 경기 중 획득하는 능력 강화 장비이므로 메인 로비 커스터마이징에 포함하지 않는다.
- 경기 외형과 능력 장비를 구분해 상대가 장비 상태를 외형으로 파악할 수 있게 한다.
- 구체적인 드로잉 입력, 저장, 네트워크 공유 방식은 구현 전에 확정한다.

## 5. 게임 대기방과 로딩

### 대기방

- 참가자는 입장 시 서버가 두 팀 중 하나로 무작위 배정한다.
- MVP에서는 직접 팀 선택 기능을 제공하지 않는다.
- 게시판 상호작용을 통한 팀 선택과 팀 색 변경은 후속 기능으로 검토한다.
- 호스트는 게임 모드와 방 설정을 관리한다.
- 모든 참가자가 준비 상태이고 양 팀 인원수가 같을 때 호스트가 경기를 시작할 수 있다.
- 맵은 대기방 설정에서 선택하지 않는다.

### 팀 식별

- 각 팀에는 서로 겹치지 않는 팀 색상을 사용한다.
- 플레이어 머리 위에 닉네임 UI를 표시한다.
- 닉네임 UI의 테두리 색상을 해당 플레이어의 팀 색상과 동일하게 표시한다.
- 기본 캐릭터에는 목도리가 없으므로 목도리 색상으로 팀을 구분하지 않는다.

### 맵 로딩

- 방장이 게임 시작을 요청하면 서버가 해당 라운드의 맵을 무작위로 선택하고 불러온다.
- 로딩 화면에는 맵 이름, 맵 이미지, 간단한 게임 목표, 조작 팁, 현재 로딩 완료 인원을 표시한다.
- 모든 플레이어가 로딩을 완료했거나 최대 30초가 지나면 경기를 시작한다.
- 제한시간 안에 로딩하지 못한 플레이어는 연결 해제로 처리한다.

### 팀 등장

- 플레이어는 각 팀의 시작 지점에 생성된다.
- 처음 5초 동안 이동과 전투 행동을 제한한다.
- 이 시간 동안 카메라가 팀원을 짧게 보여준다.

## 6. 기본 조작

| 입력 | 동작 |
| --- | --- |
| `WASD` | 이동 |
| 마우스 | 시점 조작 |
| `Left Shift` | 누르는 동안 스프린트 |
| 좌클릭 | 상황에 따라 눈 만들기, 눈덩이 던지기, 주먹 또는 장비 공격 |
| 우클릭 | 조준 |
| `E` | 물품 및 대상 상호작용 |
| `Space` | 점프 |
| `G` | 들고 있는 장비 내려놓기 |
| `Tab` | 이모션 선택 및 사용 |

같은 입력이 여러 동작에 사용될 때는 플레이어가 든 대상, 조준 여부, 카메라 방향, 상호작용 대상에 따라 현재 행동을 결정한다. 세부 우선순위는 구현 Task에서 사용자와 확정한다.

## 7. 플레이어와 눈덩이 기능

### 눈덩이 만들기

- 카메라로 눈이 쌓인 바닥을 바라보고 좌클릭을 유지한다.
- 작은 눈덩이 제작시간의 현재 기준은 1.5초다.
- 제작 게이지가 완료되면 작은 눈덩이가 만들어진다.

### 눈덩이 상호작용

- 바닥의 눈덩이에 가까워지면 아웃라인과 상호작용 UI가 표시된다.
- 이동 입력 없이 `E`를 눌렀다 놓으면 눈덩이를 든다.
- 눈덩이 앞에서 `E`를 유지하며 이동하면 눈덩이를 굴린다.
- `E`를 놓으면 굴리기를 종료한다.

### 작은 눈덩이 조준과 투척

- 눈덩이를 든 상태에서 우클릭을 유지하면 투척 자세로 조준한다.
- 조준 중에는 캐릭터가 카메라 수평 방향을 향하고 스트레이프 이동을 사용한다.
- 조준 중 카메라 FOV와 이동속도가 감소하며 스프린트할 수 없다.
- 조준 중 좌클릭을 유지해 투척 게이지를 충전하고 놓으면 충전량에 비례한 힘으로 던진다.
- 작은 눈덩이는 빠르게 날아가 플레이어에게 피해를 준다.

### 눈덩이 굴리기와 큰 눈

- 굴린 거리나 시간에 따라 눈덩이가 최대 크기까지 성장한다.
- 눈덩이가 커질수록 굴리는 플레이어의 이동속도가 감소한다.
- 장애물에 막히면 눈덩이는 멈추고 플레이어는 눈덩이 중심에서 멀어지는 방향으로 밀려난다.
- 큰 눈덩이는 양손으로 들며 작은 눈덩이보다 운반과 충전이 느리다.
- 큰 눈덩이는 포물선을 그리며 날아가고 충돌하면 넓은 범위에 피해를 준다.

### 맨손 방해

- 손에 눈덩이나 장비가 없을 때 좌클릭하면 손을 가볍게 휘두른다.
- 정확한 밀침과 경직 효과는 구현 전에 확정한다.
- 플레이어 머리 잡기는 검토 항목이며 현재 확정 기능이 아니다.

### 이모션

- `Tab`으로 여러 이모션을 선택하고 사용한다.
- 이모션에는 전투 효과가 없다.

## 8. PvP 경기 규칙

### 목표와 라운드

- 상대 팀 전원을 동시에 얼리면 해당 라운드에서 즉시 승리한다.
- 3판 중 먼저 두 라운드를 이긴 팀이 매치에서 승리한다.
- 한 라운드의 목표 플레이 시간은 약 6분이다.
- 6분이 지나도 승패가 나지 않으면 경기를 강제 종료하지 않고 환경 위험과 이동 가능 영역 축소를 강화한다.

### 기본 HP와 피해

- 플레이어 기본 HP는 100이다.

| 공격 | 기본 피해 |
| --- | --- |
| 작은 눈덩이 | 10 |
| 큰 눈덩이 | 35 |
| 눈삽 흩뿌리기 | 20 |
| 얼음물 지속 피해 | 초당 8 |

### 경기 초반

- 시작 지점 근처에 기본 눈덩이를 배치한다.
- 기본 모닥불 4개를 서버가 지정된 후보 지점 중 무작위로 배치한다.

### 팀 전멸 판정

- 한 팀의 모든 플레이어가 동시에 얼음 상태가 되면 반대 팀이 즉시 라운드에서 승리한다.
- 핫팩 부활 상호작용이 진행 중이어도 마지막 생존 플레이어가 먼저 얼면 패배한다.
- 마지막 생존 플레이어에게 `마지막 생존자입니다!` 안내를 표시한다.

## 9. 얼기, 사망, 관전과 부활

### 얼음 상태

HP가 0이 되면 플레이어는 60초 동안 얼음 상태가 된다.

- 이동, 공격, 상호작용 불가
- 얼음 오브젝트 생성
- 플레이어 충돌 유지
- 눈덩이 충돌 차단
- 생존 중인 아군 관전
- 60초 동안 아군의 핫팩 부활 가능

얼음 상태에서 추가 공격을 받아 파괴되는 규칙은 사용하지 않는다.

### 사망

- 얼음 상태가 된 뒤 60초 안에 부활하지 못하면 얼음이 녹고 해당 라운드에서 사망한다.
- 사망한 플레이어는 해당 라운드에서 핫팩으로 부활할 수 없다.
- 사망 후에도 생존 중인 아군을 관전한다.

### 핫팩 부활

- 핫팩을 가진 플레이어가 얼어붙은 아군 근처에서 `E`를 10초 동안 유지하면 부활시킨다.
- 부활 시 최대 HP의 50%로 복귀하고 3초 동안 무적 상태가 된다.
- 이동, 공격, 상호작용 키 해제, 대상과의 거리 이탈 또는 피해로 일정 거리 이상 밀리면 부활이 취소된다.
- 부활이 취소되면 핫팩을 소모하지 않는다.
- 부활이 완료될 때 핫팩을 소모한다.
- 핫팩은 캐릭터 뒷주머니에 표시한다.
- 아군은 UI 아이콘으로 핫팩 보유 여부를 확인할 수 있고, 적은 캐릭터 외형으로만 추측할 수 있다.

## 10. 선물상자

### 생성

- 서버가 맵에 미리 배치된 Spawn Point 중 하나를 선택한다.
- 시작 지점과 너무 가깝거나 플레이어 바로 아래인 지점은 피한다.
- 한 팀의 시작 지점에 지나치게 가까운 지점은 선택 확률을 낮춘다.
- 경기 시작 30초 후 첫 번째 상자를 맵 중앙과 가까운 위치에 생성한다.
- 고정 종료 시간이 없으므로 명목상 6분의 30초 전인 5분 30초에 마지막 금색 상자를 맵 중앙에 생성한다.

### 개봉과 획득

- 플레이어가 상자 가까이에서 `E`를 누르면 상자를 연다.
- 서버가 먼저 유효한 상호작용을 완료한 플레이어를 획득자로 확정한다.
- 상자 하나에는 아이템 하나가 들어 있다.
- 공격으로 상자를 개봉하는 기존 규칙은 사용하지 않는다.

### 마지막 금색 상자

마지막 금색 상자에는 다음 중 하나가 들어 있어 뒤처진 팀에도 역전 기회를 제공한다.

- 황금 핫팩
- 황금 눈삽
- 황금 눈오리 제작기
- 황금 붕어빵

### 상자 등급

- 선물상자는 파랑, 빨강, 금색 순으로 등급이 높아진다.
- 외관과 등장 아이템은 등급에 따라 달라진다.

| 등급 | 기존 등장 후보와 현재 기준 |
| --- | --- |
| 파랑 | 핫초코, 에너지 드링크 |
| 빨강 | 부츠, 패딩, 장갑, 녹슨 눈삽, 녹슨 눈오리 제작기 |
| 금색 | 핫팩, 황금 눈삽, 황금 눈오리 제작기, 황금 붕어빵, 모닥불 키트 |

- 붕어빵을 포함한 신규 아이템의 일반 상자 등급과 등급별 확률·수량은 구현 전에 확정한다.

## 11. 아이템

### 기본 원칙

- 일반적인 인벤토리는 사용하지 않는다.
- 아이템은 획득 즉시 사용하는 사용형 또는 캐릭터에 반영되는 착용·장비형으로 구분한다.
- 내려놓을 수 있는 장비는 `G`를 사용한다.
- 부츠, 장갑, 패딩과 핫팩은 캐릭터 외형에도 반영한다.

### 권장 효과

| 아이템 | 권장 효과 |
| --- | --- |
| 핫팩 | 얼어붙은 아군 1명 부활 |

| 붕어빵 | HP 35 회복 |
| 에너지 드링크 | 5초간 무적 |

### 눈삽 세부 원칙

- 기본 좌클릭은 눈삽으로 앞을 밀쳐 상대를 약간 밀어낸다.
- 땅을 보며 눈을 파서 장전하는 동안 이동속도가 감소한다.
- 장전 후 눈을 전방에 흩뿌려 넓은 범위에 피해를 준다.
- 공격받아도 자동으로 떨어뜨리지 않으며 `G`로 내려놓는다.
- 녹슨 눈삽은 2~4 사이의 무작위 내구도를 가진다.
- 황금 눈삽은 내구도 5회를 가진다.

## 12. 모닥불

- 기본 배치 모닥불과 모닥불 키트로 생성하는 모닥불은 동일한 Blueprint와 게임 규칙을 사용한다.
- 팀과 관계없이 범위 안의 모든 플레이어를 초당 HP 4씩 회복한다.
- 작은 눈덩이에 5회 또는 큰 눈덩이에 2회 적중하면 꺼진다.
- 꺼지기 직전에는 불꽃이 작아지고 연기가 증가한다.
- 경기 시작 시 기본 모닥불 4개를 배치하며, 모닥불 키트로 추가 생성할 수 있다.

## 13. PvP 맵

세 맵은 현재 MVP 범위에 포함한다. 각 라운드의 맵은 서버가 무작위로 선택한다.

### 얼음 빙하

- 얼음물 수위 상승으로 플레이 영역이 줄어드는 맵이다.
- 기본 수위 변화 기준은 다음과 같다.

| 경기 시간 | 변화 |
| --- | --- |
| 0:00~4:00 | 수위 변화 없음 |
| 4:00~5:00 | 외곽 낮은 지형 침수 |
| 5:00~6:00 | 안전 지역이 중앙으로 축소 |
| 6:00 이후 | 빠른 속도로 추가 상승 |

- 수위 상승 10초 전에 `얼음물이 차오르고 있습니다!` 경고를 표시한다.
- 위험 지역에는 바닥 균열, 물결, 경고 색상 등 시각적 신호를 제공한다.
- 물에 닿은 플레이어는 초당 8의 지속 피해를 받는다.

### 눈섬

- 배틀로얄의 자기장처럼 안전 영역이 점차 줄어드는 맵이다.
- 안전 영역 밖의 구체적인 피해와 축소 단계는 구현 전에 확정한다.

### 눈숲속

- `눈 폭`이 이동 가능 영역을 점차 줄이는 맵이다.
- 눈 폭은 배틀로얄의 자기장과 같은 기능을 하며 폭설 VFX로 경계와 위험 지역을 표현한다.
- 눈섬의 자기장과 차별화되는 피해, 이동, 시야 규칙은 구현 전에 확정한다.

### 맵 공통 오브젝트

- 기본 눈덩이: 맵에 배치되어 바로 주워 사용할 수 있다.
- 눈사람: 플레이어가 굴려 만든 큰 눈덩이와 유사한 상호작용 대상이다.
- 모닥불: 팀과 관계없이 주변 플레이어를 회복시키며 눈덩이에 맞으면 꺼진다.
- 얼음물: 플레이 가능 영역을 제한하고 접촉한 플레이어에게 지속 피해를 준다.
- 얼음물에 빠진 플레이어는 짧은 시간 수영해 안전한 위치로 이동할 수 있다.

### 라운드와 매치 결과

- 한 팀이 라운드에서 승리하면 모든 플레이어의 조작을 멈추고 3초 동안 승리 상황을 보여준다.
- 아직 어느 팀도 2승하지 못했다면 다음 무작위 맵 라운드로 이동한다.
- 한 팀이 2승하면 매치 결과 화면으로 전환한다.
- 결과 화면에는 승리 팀, 대기방으로 돌아가기, 방 나가기를 표시한다.

### 눈사람 감염 모드

눈사람 감염 모드는 현재 MVP 이후에 여력이 있을 때 개발한다.

- 무작위 플레이어 한 명이 눈사람으로 시작한다.
- 눈사람과 접촉한 일반 플레이어는 일정 시간 뒤 눈사람으로 변한다.
- 일반 플레이어는 눈덩이로 눈사람을 공격하고 치료제로 감염을 해제할 수 있다.
- 후반에는 무적 아이템을 제공할 수 있다.
- 눈사람은 모든 일반 플레이어를 감염시키면 승리한다.
- 일반 플레이어는 제한시간 종료 시 한 명이라도 생존하면 승리한다.
- 눈사람은 일반 플레이어보다 빠르다.
- 정확한 제한시간과 감염 단계는 구현 전에 확정한다.
